# 流水 · 后台管理形态 demo

> 这版 demo **不推翻** `~/Desktop/liushui/README.md` 里「后台上线仍推迟」那条。
> 它的用途是把后台形态先对齐清楚 —— 讲得出后台要管什么、闸门卡在哪、钱怎么算出来的，
> 而不是现在就上线。

PRD v0.2 的十三章全在写面向用户和创作者的那一面，但它同时创造了一批只能在后台完成的
义务（审核门槛、有效使用者判定、外部数据授权、隐私复核、四个北极星数）。这个 demo 把那些
义务落成能点的界面。

### 一个在做 demo 时发现的问题：双判官只有一个在跑

`skills/resume-jd-match/skill.json` 的 pipeline 里声明了

```json
{ "step": "rule_score", "impl": "whatajob-match-v3", "out": "match.ruleScore",
  "note": "只写入 meta，不进 prompt" }
```

输出 schema 里也声明了 `meta.ruleScore`。但 `backend/` 里 `grep ruleScore` **零命中**，
每个 run 文件的 `meta` 只有 `elapsed` / `prompt_tokens` / `completion_tokens` /
`provider` / `model` / `attempt`。

也就是说 **D7「分歧是资产」现在还取不到** —— 两个判官只有模型这一个在跑，分歧率没有真实
数据源。复核队列页把这条横幅放在分歧率**上面**，就是为了让分歧率没法被读成一个观测值。
队列里每条分歧都带 `modelSource` / `ruleSource` 标明来源是实跑、取自文档、还是构造。

### 简历片段的来源

复核队列展示的简历内容取自 `skills/resume-jd-match/fixtures/resume-pm-recsys.txt`，
**手造，不是真实学生简历**。`skills/resume-jd-match/README.md` 和 `backend/README.md`
都写了「别用真实学生简历」，demo 里不破例。JD 原文是真实公开岗位描述。


```
├─ 审核
│   ├─ 工具审核        ★ 做深
│   └─ 内容审核          占位
├─ 创作者
│   ├─ 创作者列表        占位
│   └─ 月度结算        ★ 做深
├─ 质量
│   ├─ 复核队列        ★ 做深   ← D7
│   ├─ 需求池          ★ 做深   ← D9
│   └─ skill 质量看板  ★ 做深
├─ 供给
│   ├─ 插槽管理          占位
│   └─ 场景配置          占位
├─ 数据源台账        ★ 做深   ← PRD §八
└─ 系统
    ├─ 操作审计         轻量，所有写动作的落点
```

四个占位页不是空白，是**只读的具体视图 + 一段「为什么不是这一版做」**。
半成品比空白更容易被误当成已实现，所以占位页顶上都有「占位」chip，侧栏也标。

### 六个做深模块各自的要点

**工具审核** —— 门槛是难点 2 的工具契约，不是人工感觉。抽屉右栏六项逐条算：读取 / 产出
（D6：`match.report` 不能叫 `resume`）/ 写回 / 接入等级 L0-L1-L2 / 外部数据逐项授予 /
积分明细加总必须等于标价。有硬性不合项时「通过」按钮是锁死的，点了会拒。打回必须选理由 ——
理由要能聚合成创作者指引。

**月度结算** —— PRD §七 给了「有效使用者」的判定表，但一个总数不可复核，所以做成逐项扣除
的账单，每项可展开看被排除的样本：1284 → −312 −86 −41 −398 −27 −8 → **412** →
×1.18 质量系数 → +奖励 → 受月度上限约束 → 应付。质量系数六项沿用创作者中心的口径，
**后台算出来的 1.18× 与前台创作者中心显示的一致**，否则两个 demo 自相矛盾。
林霖学姐那条会触发上限行（应发 ¥15,428.29，上限 ¥12,000.00）。

**复核队列** —— D7。两个判官并排显示且各带来源行，判「谁对」之后必须归因到修复位置
（词典缺词 → `_SKILL_KEYWORDS` / prompt 规则 → `prompt.md` 九条 / 模型错判 → eval 语料 /
判据不清 → 需要一条新决策），然后进待修清单。页里有一张「为什么不把规则分喂给模型」的卡
（双盲阅片）。

注意：**判定一条不会改变分歧率**。分歧率是「已经发生过的分歧 / 总 case」，是质量指标；
判完只会让待复核队列少一条。这一点和原计划里「分歧率随之变化」的写法不同，按前者实现。

**需求池** —— D9。兜底率折线带阈值线（15%），越线不是提醒是 bug。当前连续 3 周越线。
八个未覆盖聚类可标立项。同页有黑话别名层（双非 / 海本 / 保底校 / 冲刺校 / 一面二面 /
对标 / 润…）可增删 —— 「润」故意留了注：它是歧义词，没法在表里钉死成一个意思。

**skill 质量看板** —— 见上文。另外单独一块写 D12 那类不变量抓不到的错判：拿职责描述当
性格证据，引用逐字没错、推论是编的，三条机械不变量对它是盲的。

**数据源台账** —— PRD §八：外部数据是权限，不是默认能力。新鲜度按难点 4 分级（学校专业
年更 / 申请截止 季更 / 录取要求 年更 / 往届案例 持续 / 签证政策 事件驱动·强制展示日期）。
当前「录取要求」已过期。

## 技术栈与设计系统

Vue 3 + TypeScript + Vite 7 + Vue Router 4（hash）+ Pinia + Tailwind v4（`@tailwindcss/vite`）。
纯 Tailwind 手写，不引组件库 —— 表格排序、抽屉、Tabs、Toast 都是自己写的，demo 量级够用。

**`src/index.css` 的 `@theme` 块是从 `app/src/index.css` 逐字搬过来的。**
Tailwind v4 的 CSS-first 配置是纯 CSS、与框架无关，所以 React 项目的色板 / 阴影 /
`@keyframes` 在 Vue 里直接可用。没有抽共享文件（跨项目根的 Vite 解析要开 `server.fs.allow`，
为一个 demo 增加启动失败面），代价是**改了前台色板要手动同步过来**，文件头留了注释。

同色不同密度：色板、字体、圆角、按钮质感全沿用，装饰按场合降级。

| | 前台 | 后台 |
|---|---|---|
| 主色 / 字色 / 强调色 | `#00b4d8` / `#0a2540` / `#ff8360` | **完全相同** |
| 卡片圆角 | 20px | 16px |
| 卡片底色 | `white/85` + `blur-xl` | `white/92` + `blur-md` |
| 正文字号 | 15 / 14 / 12px | 13 / 11 / 10px |
| `btn-water` | 同一条渐变、同一个 pill | padding 24→20px |
| 波浪 / 流动光斑 | 到处都有 | **只在总览页头** |
| 气泡 / 点击涟漪 | 有 | 完全不移植 |
| 行高 `leading-relaxed` | 1.625（Tailwind 默认） | **1.8** |
| 正文字距 | 0 | **0.012em** |
| 标题字距 | `tracking-tight`（−0.025em） | **0** |

### 中文排版是后台独有的一层，不要同步回前台

Tailwind 的行高与字距默认值是照拉丁文字调的。前台正文 14–15px 用默认值没问题，
后台压到 11–13px 就不行了 —— 汉字是满字身，没有 x-height 留出的空气，1.625 的行高
在 11px 下会挤成一片；反过来标题上的负字距（`tracking-tight`）在汉字上会让笔画相碰。

`src/index.css` 里追加了**第二个 `@theme` 块**只改 `--leading-relaxed` / `--leading-snug`。
Tailwind v4 会合并多个 `@theme`，所以这一个变量改完，全项目 56 处 `leading-relaxed`
一起跟着变，前台逐字搬来的那个 `@theme` 块一个字没动。另有三条 base 规则：
`body` 加 0.012em 正字距（数字列另有 `tabular-nums`，对齐不受影响）、
标题字距归零 + 行高 1.35 + `text-wrap: balance`、段落 `text-wrap: pretty` 防末行掉单字。

### 界面上不写理由

每页副标题只有一句「这一页要干什么」。PRD 章节号、决策编号（D 几）、难点编号
**一律不出现在界面上** —— 连着翻五页，每页顶一段说明就没人看了。要追出处回这份 README
和决策记录。同理，结算账单里每行扣除的依据只在不自明时才写一句（「同人同工具每月只计一次」
要写，「未登录用户」不用），契约检查表的六项只标规则名不标出处。

界面上必须保留的是**诚实声明**，那几条不能删：规则判官未接入所以分歧率不是观测值、
隐私高亮不是真实识别结果、本页金额为构造数据、简历 fixture 非真实学生简历。

水元件从 `app/src/components/water/Water.tsx` 移过来六个（`LiquidOrb` `LiquidBar`
`FlowField` `WaveDivider` `CountUp` `Sparkline`）。React 版全是 `useState` +
`setTimeout` 触发一次过渡，换成 `ref` + `onMounted` + `watch`，逻辑不变。
`Bubbles` / `Ripple` 不移植。

表格行**不上浮**，只换底色 —— 前台卡片 hover 上浮 5px，两百行里任何一行的鼠标经过都会把
整张表推得晃。数字列一律 `tabular-nums` + 右对齐，账单要逐行竖着核。
系统开「减少动态效果」后 21 个动画元素全部被压到 1μs。

## 做 demo 时踩到并修掉的三个渲染问题

记在这儿是因为这三个都属于「看着好像没坏」的类型：

1. **`LiquidBar` / `LiquidOrb` 的渐变被整条丢掉。** 前台传的 tone 是 `#00b4d8` 这类
   十六进制，代码里直接拼 `${tone}aa` 得到带透明度的色；后台到处传 `var(--color-water-500)`，
   拼出来是 `var(--color-water-500)aa` —— 非法 CSS，整个 `background` 声明被丢弃。
   表现是进度条和液面球看着是空的。改用 `color-mix(in srgb, <color> N%, transparent)`，
   两种写法都成立。
2. **粘性表头滚到一半列名就没了。** `th` 上 `sticky top-0 z-10` 都写了，但粘性贴的是**最近的
   滚动口**，而外层 `.panel` 带 `overflow-hidden`（圆角要裁表格边缘）—— 它就是那个滚动口，
   且自己不纵向滚，于是表头跟着面板一起滚出去。`.t-wrap` 上原来的 `overflow-x-auto` 让情况
   更糟（规范里一轴 auto 另一轴 visible 会被强制成 auto，又多一个不滚的滚动口）。
   改成让 `.t-wrap` 自己成为滚动口（`max-h` + `overflow-y-auto`）。
   顺带把 `border-collapse` 换成 `border-separate`：collapse 下 Chrome 不认表头单元格的
   z-index，表头会被滚上来的行盖住。
3. **「重置演示状态」按钮看着没反应。** 六个 store 都是创建时 `load()` 一次种进内存的，
   只清 `localStorage` 页面不会变（计数还停在打回后的值），演示的人会以为按钮坏了。
   现在清完直接 `location.reload()`。

另外 `index.html` 补了 favicon（复用前台的 `wave.svg`），否则浏览器隐式请求
`/favicon.ico` 拿 404，演示时控制台带着一条红色报错。
