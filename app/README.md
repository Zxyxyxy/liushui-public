# 流水 · 学生 AI 目标达成平台（产品原型 Demo）

> 流水不争先，争的是滔滔不绝。

基于 `outputs/student-ai-platform-architecture-v0.1.md` 做的可交互产品原型。不是静态 HTML 页面，而是一个真实的 React 应用：有路由、有状态、有持久化。

## 运行

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # 生产构建
```

## 技术选择

| 项 | 选择 | 理由 |
|---|---|---|
| 构建 | Vite 8 | 唯一的 `index.html` 只是挂载壳，页面全是组件 |
| 框架 | React 19 + TypeScript | 页面跳转与交互状态都要真做 |
| 样式 | Tailwind v4（CSS-first `@theme`） | 色板、动效、阴影集中在 `src/index.css` 一处定义 |
| 路由 | React Router 7 | 七个页面 + 两个详情页动态路由 |
| 状态 | Context + localStorage | 积分、收藏、运行记录跨页面跨刷新保留 |

**没有接入任何真实 AI 接口。** 所有运行结果来自 `src/lib/mockRun.ts` 的预写内容，意图识别来自 `src/lib/intent.ts` 的关键词权重匹配。

## 设计主题：水

主题"流水不争先，争的是滔滔不绝"落到了具体的视觉元件上，不只是配色：

- **配色**：`#00b4d8` / `#90e0ef` / `#caf0f8` 三色扩展成 50–900 完整色阶（`--color-water-*`）。正文用深水墨色 `#0a2540` 而非纯黑，避免沉闷。四个场景各配一个高识别度强调色（珊瑚橙、日光黄、薄荷绿、雾紫），保证蓝色主调不单调。
- **波浪** `WaveDivider`：两层不同速度、反向滚动的 SVG 路径叠加，分区之间是真实起伏的水面而非直线。
- **流动光斑** `FlowField`：三个大尺度模糊渐变圆各自 24–38 秒周期漂移，叠一层水下焦散光纹。
- **气泡** `Bubbles`：缓缓上升并横向偏移，出现在首屏、上传拖拽区、运行中面板。
- **点击涟漪** `Ripple`：从触点扩散，包在工具卡片、场景卡、点赞按钮上。
- **液面进度** `LiquidBar` / `LiquidOrb`：进度条和指标环都是"注水"动画，液面上有掠过的高光和起伏的波形。
- **卡片**：`.glass` 半透明玻璃质感 + 上缘一道水线高光（表面张力），悬停时上浮 5px 像被水托起。

配色与动效全部在 `src/index.css` 的 `@theme` 块里，改一处即可全局生效。`prefers-reduced-motion` 下所有动画自动关闭。

## 七个页面

| 路由 | 页面 | 核心交互 |
|---|---|---|
| `/` | 首页 | 需求输入 → 意图识别 → 三类路由推荐；场景入口；最近使用；推荐工具；热门帖子；创作者 |
| `/market` | 工具市场 | 搜索（含顶栏下拉联想）、五维筛选、四种排序、收藏 |
| `/tool/:id` | 工具详情 | 三个 Tab（说明 / 示例输入输出 / 评价）、逐步积分明细、外部数据声明、相关帖子反向展示 |
| `/tool/:id/run` | 工具运行 | 文件拖拽上传（带进度）、积分确认弹窗、逐步执行动画、结果分块浮现、四种后续动作 |
| `/workspace` | 个人工作台 | 五个 Tab（总览 / 资料 / 运行历史 / 时间线 / 收藏）、待办勾选与新增、进度液面 |
| `/community` | 社区 | 场景筛选、三种排序、搜索、帖子里最常被提到的工具 |
| `/community/:id` | 帖子详情 | 结果前后对比、点赞收藏、发评论、侧栏工具可直接跳运行 |
| `/creator` | 创作者中心 | 数据总览（质量系数六项指标环）、我的工具、激励结算明细、三入口发布流程 |

## 能走通的完整链路

1. **逛市场找工具**：首页场景卡 → 市场筛选 → 工具详情 → 运行页 → 上传文件 → 积分确认 → 看结果 → 保存到工作台
2. **描述需求被推荐**：首页输入"考研还有 100 天，三科并行不知道怎么排计划" → 识别为长期目标 → 推荐学习计划 + 学习规划师 → 提示建工作台
3. **帖子带动工具使用**：社区 → 帖子详情看到前后对比 → 侧栏"直接运行" → 运行页
4. **结果转内容**：运行完成 → 发布经验帖 → 自动生成标题摘要标签、勾选隐去隐私 → 获得 30 积分
5. **创作者发布**：创作中心 → 描述创建 → 生成初稿 → 调定价滑块 → 提交审核 → 冷启动保护说明

## 积分（仅视觉展示，不接支付）

按文档 §7 实现：

- 顶栏常显余额，数字变化有滚动动画；点开是账户弹窗（余额水池 + 消费记录 + 演示充值/签到）
- 工具卡片、详情页、运行页都显示"消耗 N 积分"
- 运行前必须确认，弹窗列出**每一步的实际扣费**且加总等于总价（工作流不隐藏步骤费用）
- 余额不足时确认按钮禁用并提示还差多少
- 反复强调：文件上传、存储、预览、工作台保存**不扣积分**；运行失败不扣积分

## 数据

`src/data/` 下是纯数据，改这里就能改 Demo 内容：

- `tools.ts` — 28 个工具（22 单点工具 + 4 AI 专家 + 2 工作流），覆盖文档 §12.1 的四个场景。重点工具（简历修改、JD 匹配、选校定位、文书诊断、Excel 公式、PPT 大纲、学习计划）有完整的输入字段和真实感的示例输入输出
- `posts.ts` — 8 篇社区帖，每篇有完整正文、关联工具、部分带结果前后对比
- `creators.ts` — 6 位创作者，覆盖平台认证 / 专业人士 / 机构 / 企业 / 个人五种认证标签
- `workspaces.ts` — 3 个工作台（秋招 / 留学 / 课程项目），各有文件、待办、时间线、运行历史

积分/收藏/运行记录写入 localStorage（key `liushui.v1`）。顶栏头像菜单里有"重置演示数据"。

## 已知边界

- 无后端、无账户、无真实文件解析。上传的文件只读文件名和大小，不读内容
- 意图识别是关键词权重匹配，不是模型推理。输入完全无关的内容会退化为按场景热度推荐
- 工具评价、部分评论是固定内容，不随工具变化
- 仅桌面端优化（文档要求 Web 桌面端优先）；移动端可用但未精细调整
